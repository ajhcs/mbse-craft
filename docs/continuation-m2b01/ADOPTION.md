## Adopted decisions

| Draft decision | Source implementation |
| --- | --- |
| D01 | Separate experimental `mbse-craft.native-views/1`; unbound recovery uses `mbse-craft.native-views-recovery/1`. No migration of the draft profile. Native `kernspan.stage1/2`, schema2 and native record serialization stay unchanged. |
| D02 | Bound sidecars require DocumentId, exact accepted native artifact SHA256 and snapshot SHA256 from a sealed `Session::native_checkpoint()`. Open and successful native Save are the only sources. A consumed failure and a public IoTicket cannot mint it. Historical accepted checkpoints are distinguished from current live state. |
| D03 | Typed ViewId, OccurrenceId and VisualEdgeId share one monotonic positive u64 allocator, encoded as canonical decimal strings, including native IDs inside this new wire profile. Native RecordId allocation is untouched. `sidecar_id` is a persisted opaque identifier derived from the unique initial runtime nonce; it confers no runtime authority. |
| D04 | Persist current state and allocator high-water. Undo, Redo, runtime proofs, selections and pending jobs are not serialized. Undo, Redo and removal never rewind presentation high-water. |
| D05 | Model, field text and Layout Undo/Redo remain distinct. Layout controls are explicitly labeled. Field focus keeps existing native text history policy. View titles, geometry, camera, visibility and pin state do not mutate the evaluator/native stamps. |
| D06 | Every layout transaction/history restoration validates document, native record ID/kind and edge endpoint identities. Missing/wrong-kind active targets refuse the whole restoration before a history pop. No semantic resurrection, label-based retarget or semantic Delete. |
| D07 | Freeze layout alongside the native request. Only after the native controller verifies current success can a sealed checkpoint bind that captured layout. Native and views acknowledge independently; later layout edits remain unsaved after an older views acknowledgment. Neither two-file atomicity nor filesystem CAS/power-loss safety is claimed. |
| D08 | All desktop semantic commands and model/text Undo/Redo use `Views::dispatch`: clone only Editor, stage view consequences, validate, recheck native/view stamps, then publish both. Session and I/O reservations are never cloned; no native record map mutation is introduced. |

Two named views seed the default canvas. Additional occurrences, including duplicates within one view, require explicit Reuse. Names and semantic fields are always read from native records. Removing or hiding an occurrence leaves the semantic record/relations intact. The primary view cannot close. The canvas renders stored occurrence geometry and explicit edge endpoints; the complete native relation ledger stays available. Fit changes the view camera only; viewport allocation is capped at32768 pixels per axis, with Fit available for distant geometry. Dense labels/layout/accessibility have no new acceptance claim.

Only three closed semantic keys persist edge endpoints: Capability contributesTo Mission, Objective typed subject, Measure forObjective. Keys contain owner, role, target and target kind; edges bind exact source/target occurrences. This implementation attaches endpoints, not arbitrary bend-point routing. Other arrows are derived only when visible endpoints are unique; ambiguity is disclosed and every semantic relationship remains in the ledger. No parallel stored semantic graph/resolver is introduced. Validation/transition uses temporary indexes derived from the existing authoritative graph rather than deriving the full graph for every edge.

## Histories and bounds

Adopted limits:16 views,4096 total occurrences,8192 edges,1024 occurrences/view,1024 UTF8 bytes/title,8MiB encoded sidecar, finite coordinates/sizes within +/-1,000,000 units, positive sizes and zoom0.05–20. Detached records count against the same limits. Input byte bounds precede JSON acquisition; recursive duplicate-key rejection precedes typed map admission. Collection counts are checked before typed-map construction. The bounded JSON value parser can still allocate from an at-most8MiB input; no total RSS bound is asserted.

Layout history retains at most64 snapshots and8MiB of accounted encoded presentation payload across Undo and Redo. Oldest past entries are evicted on a new action; if a replacement cannot fit, it refuses before changing history/state. Candidate/live snapshots and Rust allocation overhead are outside this payload accounting. Native history retains its existing policy. Runtime reactivation proofs are pruned to presentation IDs reachable in current and retained history documents, including after removal, view close and history eviction; no orphan-proof growth is retained.

A native Undo that removes a target detaches occurrences/edges with exact IDs/geometry and a visible reason. Reactivation requires a matching actually observed model Redo, reversed native record-state hashes and the same runtime instance. Reopened/restored views have no such proof. Arbitrary same-name/same-number data cannot reactivate detached items. Undoing a layout removal revalidates its native target and exact edge pair; missing targets refuse atomically. Layout edits preserve native Redo branches. Transient active-view, occurrence selection, drag and route endpoints are reconciled after commands/history/open; missing active views cannot cause a canvas indexing panic.

## Persistence, recovery and navigation

View jobs and receipts are sealed and bind document/runtime, native request identity, exact native binding, view revision, destination and frozen bytes. A late acknowledgment may record the older artifact but cannot mark a newer layout saved. Native success/views failure keeps the native Save and live geometry, reports separate states and offers retry/recovery. Failed native acknowledgment never starts a bound views write. A fallible views-worker start consumes only its owned pending ticket, preserves geometry and leaves native Save intact; the injected test never exhausts resources. The pre-existing native worker launcher is unchanged and still has its previous start-failure qualification limit.

Cheap per-frame saved/recovery hints compare runtime freshness and view revision, without full sidecar serialization or file I/O. Hints do not authorize leaving the layout. `Io::verify_preserved` bounded-reads the acknowledged sidecar/recovery path, checks its exact disk SHA and canonical current-content digest, and revalidates the native checkpoint for bound files. The desktop applies this gate before load/continue/close; recovery continuation additionally requires existing `Session::recovery_current()`. Delete, truncation, tamper, later edits and stale completions refuse continuation while retaining memory. Exact disk hash and canonical state digest are separate for valid noncanonical JSON input.

Sidecar paths are explicit local `.mbse-views.json` files. There is no ambient sidecar search or path-hint I/O. Missing/corrupt/future/mismatched inputs do not replace the current/default canvas. Original files remain unchanged; paths of rejected admitted-size inputs stay protected, with the most recent bounded bytes/reason retained in memory. No future-profile rewrite or native-file repair occurs. SaveAs refuses an unowned existing leaf; a racing arrival/symlink is refused by private Craft staging plus exclusive hard-link placement. Updating an acknowledged owned sidecar uses actual Craft atomic storage, cooperative locking, checked prior hash and retained private prior bytes. Noncooperating writers can race final replacement: no cross-process CAS claim. Unsupported hard links fail rather than fall back to an overwriting operation.

Unbound recovery has no native artifact hash. Native recovery creates a different DocumentId, so the old bound sidecar and old unbound views recovery are refused/preserved rather than automatically rebound. Explicit presentation-copy/reconciliation into a recovered native document remains deferred. This slice does not claim lossless automatic aggregate project recovery.
