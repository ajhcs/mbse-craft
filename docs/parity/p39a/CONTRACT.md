# P39a append-only native admission transaction

P39 is split into a native transaction core (P39a), strict source adapter/loss review (P39b), and native Apply/Undo/save/cold acceptance (P39c). This core accepts an explicit caller-declared payload, not arbitrary XML or proof of source truth. Source verification and unsupported-construct refusal belong to P39b; no editable source compatibility claim follows from this PR alone.

Prepare creates a sealed candidate over an exact native runtime, model/raw revision and full snapshot hash. Only existing component definitions and Part/Reference usages are created. An explicit source model maps to a selected existing native System without renaming it. Optional Block declarations remain documentary profile metadata on an existing component definition, never a new semantic engine or full SysML reclassification.

All source IDs must be unique within the payload; usages must reference definitions in that payload. Fresh IDs come from the existing global allocator. Existing native type/store/profile validators enforce cycles, names, target kinds and shared quotas. A fixed app-owned correspondence profile records exact member, primary hash, local source ID, source kind, source name, namespace and adapter rule. Conflicting profile declarations and previously attached identical source identities refuse instead of overwriting or reusing native objects silently.

Prepare changes nothing. Apply rechecks runtime/hash freshness and uses the existing Editor typed command to publish all definitions, usages and metadata as one model-history entry. Invalid payloads, stale/foreign plans, quota/allocator/revision exhaustion or incompatible targets leave the complete model, raw journals and allocator unchanged. Existing invalid drafts, opaque namespaces and all other meaning survive. Undo removes the new accepted data and metadata together, retains newer raw drafts, and never rewinds IDs; Redo restores the same accepted identities. Saved/cold/recovery data and all eight presentation maps remain exact.

Bound each payload to 64 source identities, including its model and Block declarations. Keep encoded request data below128KiB. These are logical limits, not performance/RSS qualification. No file I/O, source acquisition, parser, evaluator, presentation changes or target migration is added here. Source adapter/native acceptance, all56 broad specifications and integrated exits remain open.
