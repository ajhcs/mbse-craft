# P25 local coverage and change impact

Build on P24 PR30 merge0c528b7d. Read-only queries use the existing assurance Board,
native/type endpoint resolver, deletion authority's uninterpreted-impact detector,
calculation context and evidence staleness/provenance rules. No second model,
reference or calculation engine; no query writes, status promotion or proof reuse.

Report every admitted requirement in stable local-ID order. Missing Satisfy counts
only active declared Satisfy endpoints; missing Verify counts only active declared
Verify case endpoints. Other kinds and display labels never satisfy either query.
An isolated root has no parent/children and no typed dependencies touching it.
These are local declaration inventories, not engineering satisfaction/test verdicts.
Detached native identity is retained and cannot contribute an active link.

Potential impact walks supplier-to-client typed requirement dependencies and
containment children iteratively with a visited set. It lists possible requirements,
traces and retained evidence to review; it does not rewrite these records or infer
that every possible effect is known. Unknown register/requirement/anchor/evidence
metadata and native uninterpreted fields/namespaces are explicitly disclosed with
total count and first128 locations. Unsupported relations remain opaque; no implicit
interpretation, full reference coverage or safe-to-delete/engineering verdict.

New evidence captures an optional dependency hash over accepted requirement and
supplier/ancestor context, exact kind/endpoints and documentary test specifications.
Trace labels and verification-status display are excluded from semantic selection.
Master/source changes stale existing consumer evidence even when the consumer
record/revision stays unchanged. Existing old evidence without a captured context
cannot become qualified when dependencies appear. Flat legacy evidence with no
dependency remains empty-omitted on wire. Context hashes prove comparison only,
not source truth or runtime evaluator ownership. Cold native evidence still lacks
the existing runtime proof; no serialized hash can manufacture Passed.

Queries evaluate freshness on a background frozen clone using existing context;
unavailable current context is an explicit warning. At most256 evidence rows are
assessed per query; unexamined total is explicit. UI renders first128 requirements,
evidence, detached and impact IDs; complete report/accepted register remain retained.
Native/model/raw/config and exact register/form bytes bind current UI results;
newer edits make delayed results stale and disable their navigation. Selection-only
navigation preserves query root and accepted data. Query/report state is transient;
no saved query acts as current cold proof. Independent register Save and native
Save remain separate and retain all prior raw/source/view data.

Acceptance includes exact known missing-link/orphan IDs, upstream-context staleness
with immutable old receipt and unchanged consumer, label-only stability, detached/
unknown disclosure, iterative cycles, explicit query limits, actual native query
and exact selection, stale-result refusal, Save/cold query and unchanged native
Snapshot/presentation maps. Same-agent bounded Linux scope; all broad specs and
integrated milestone/independent/full NoMagic/SysML/Craft acceptance stay open.
