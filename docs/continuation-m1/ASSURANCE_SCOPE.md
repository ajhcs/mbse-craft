# Application requirements and evidence register

`mbse-assurance` owns `mbse-craft.requirements-evidence/1`, a separate JSON sidecar. It does not reclassify native Objectives/Measures or external normative requirements. Source anchors preserve original IDs, artifact hash, metamodel, unit strings, references, unknown metadata and independent package/parse/resolution/projection/admission/execution status.

Maturity, implementation and verification are independent source-backed enums. Maturity Approved cannot imply implementation or verification. Empty statement edits remain invalid raw drafts beside the last accepted statement. Register Undo/Redo traverses explicit register operations; open resets interactive history, preserving persisted drafts and unknown metadata. This register has no scalar evaluator.

`attach_calculation` calls the actual existing Editor evaluator, retaining exact serialized receipt bytes/hash, stamp, config/input/tool hashes and selected typed quantity. 120m/8s yields15m/s through that engine and remains unreviewed evidence. `attach_local_evidence` hashes an explicit bounded local file; paths never execute or fetch. Adequacy review and recorded verification are explicit distinct operations. Passed refuses missing, stale, failed, unsupported, cancelled, unreviewed, inadequate or mutated evidence and incomplete raw requirement drafts. Changing model/raw/config/inputs/tool, requirement or artifact invalidates freshness. `verification_current` must be checked when displaying a historical decision; a stored enum is not a current authority claim.

`save_new` uses real Craft private create-new persistence. `replace` requires exact prior disk hash and refuses a conflict. Save failures preserve current register and source bytes. A noncooperating writer can race final replacement; filesystem compare-and-swap and power-loss acceptance are not claimed. Open bounds bytes and rejects duplicate JSON keys/profile/integrity errors, retaining unknown fields only through explicit opaque maps. Source models and native sessions are never mutated. No external executor, PLM/ReqIF adapter, generic SysML engine, engineering approval authority or service is introduced.

Shared lifecycle vocabulary retains `CompletedUnsuccessful`, `CompletedFailed` and `CompletedPassed` as distinct source-backed labels. `Approved` is a requirement maturity decision; it is not application or engineering acceptance. Kernspan extends its existing requirement attributes and trace register through its own chosen schema or sidecar. Sharing vocabulary and provenance gates does not share Rust structures or imply format interchange acceptance.

Native calculation authenticity lives in nonserialized evaluator-owned proof maps over the complete retained evidence. Matching serialized stamps establish freshness only. Opening a sidecar clears live proof; historical reviews and verification decisions remain visible but cannot silently become current native execution authority. Adequacy reviews and verification decisions append immutable audit entries. Undo preserves those historical entries while changing current register state. Selected successful output may be attached when an unrelated calculation fails: the full global receipt and its failure status remain retained, and the selected output never manufactures global success.

Resource boundary: all currently attached original evidence artifacts total at most8MiB; each local acquisition also retains its8MiB per-file cap. Before an attachment clones the register for a transaction, a counting serializer streams the exact prospective envelope, including decimal JSON expansion of every byte in `Vec<u8>`, enforcing the32MiB serialized-document cap without allocating that encoded copy. Every transaction checks its existing and proposed serialized envelope and rolls back an over-budget edit atomically. Count limits are additional bounds. Refusal retains the current register so normal editing and saving can continue; these are encoded-data budgets, not a measured process-RSS bound.
