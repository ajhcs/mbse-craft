# Narrow source-edit route after semantic-set2

Status: subsequent batch proposal within the authorized continuation, not implemented or qualified. It complements typed source inspection and remains separate from conversion into the closed Stage1 ontology. Original/private sources stay read-only. No new evaluator or external runtime is proposed.

First versioned write profile: `mbse-craft.external.xml-edit/1`, initially only an existing unqualified `name` attribute on an explicitly supported, identified Capella7.0 semantic element from a recognized UTF-8 primary XML document. The exact supported class/field table must be published from the pinned metamodel before implementation. Documentation/typed-property edits follow only with their own field rules. Missing attributes, unknown source kinds/namespaces, AIRD layout and MDZIP container mutation remain explicit unsupported cases; raw-copy export remains available.

A patch plan binds the complete frozen source-set digest, member/content hash, original ID or disclosed span anchor, exact namespace/classifier, attribute byte range and original encoded bytes. It retains the original decoded value and proposed text separately. Commit freshly reads every admitted physical source and companion through the bounded reader and refuses changed digests/spans/keys. It never substitutes an ambient source or trusts a remembered hash. New text must be valid UTF-8/XML and escaped for the existing quote delimiter. No DOM-wide pretty printing, unknown-data normalization or source-file overwrite occurs.

Commit creates an owned new destination using the actual private create-new persistence path. The resulting XML is reparsed under the same bounds. Tests compare all original IDs, source-aware reference endpoints, unit/source metadata and every byte outside the explicitly replaced attribute range. A new source-set identity is computed; it is never called the prior artifact. The receipt distinguishes exact unchanged bytes from partial semantic validation and reports name-based/external-consumer meaning not established by persisted-ID checks. A syntactically valid rename is not Arcadia engineering or tool interoperability acceptance.

MDZIP write coverage needs a separate archive policy for raw member payloads, central metadata, comments/extra fields, checksums/signatures and application expectations. Preserving uncompressed unknown members alone cannot establish whole-container fidelity. Until that policy and actual fresh-copy reparse tests pass, refuse semantic archive writes with an actionable loss reason. Never patch an arbitrary XML member or omit opaque attachments silently.

Native workflow: select a known source element, edit a retained proposal, inspect exact field/source/version and losses, create a new copy, then explicitly open the new source snapshot. Stale or failed writes retain the proposal and active accepted/native state. Unsaved proposals and pending writes require deliberate close/cancel policy; no earlier copy-success receipt proves a pending-write race. Repo fixtures stay original synthetic; actual private inputs are only read, and experiments use owned new copies.
