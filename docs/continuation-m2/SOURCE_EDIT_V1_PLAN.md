Missing attributes, unknown source kinds/namespaces, AIRD layout and MDZIP container mutation remain explicit unsupported cases; raw-copy export remains available.

A patch plan binds the complete frozen source-set digest, member/content hash, required unambiguous original ID and disclosed XML byte span, exact namespace/classifier, attribute byte range and original encoded bytes. It retains the original decoded value and proposed text separately. This initial profile freshly reads the sole admitted primary through the bounded reader and refuses changed digests/spans/keys; companion sets remain unsupported. It never substitutes an ambient source or trusts a remembered hash. New text must be valid UTF-8/XML and escaped for the existing quote delimiter. No DOM-wide pretty printing, unknown-data normalization or source-file overwrite occurs.

Commit creates an owned new destination using the actual private create-new persistence path. The resulting XML is reparsed under the same bounds. Tests compare all original IDs, source-aware reference endpoints, unit/source metadata and every byte outside the explicitly replaced attribute range. A new source-set identity is computed; it is never called the prior artifact. The receipt distinguishes exact unchanged bytes from partial semantic validation and reports name-based/external-consumer meaning not established by persisted-ID checks. A syntactically valid rename is not Arcadia engineering or tool interoperability acceptance.

MDZIP write coverage needs a separate archive policy for raw member payloads, central metadata, comments/extra fields, checksums/signatures and application expectations. Preserving uncompressed unknown members alone cannot establish whole-container fidelity. Until that policy and actual fresh-copy reparse tests pass, refuse semantic archive writes with an actionable loss reason. Never patch an arbitrary XML member or omit opaque attachments silently.

Native workflow: select a known source element, edit a retained proposal, inspect exact field/source/version and losses, create a new copy, then explicitly open the new source snapshot. Stale or failed writes retain the proposal and active accepted/native state. Unsaved proposals and pending writes require deliberate close/cancel policy; no earlier copy-success receipt proves a pending-write race. Repo fixtures stay original synthetic; actual private inputs are only read, and experiments use owned new copies.

## Write/read coverage and qualification limits

The initial exact classifier table is ctx/7.0.0 `Mission`, `Capability`, and `SystemComponent`; inherited EString name ownership is pinned in [NAME_ATTRIBUTE_PRIMARY_AUDIT.md](NAME_ATTRIBUTE_PRIMARY_AUDIT.md). Only owned elements with an original ID and an existing unqualified name attribute qualify. An XML document may have no declaration or a literal XML 1.0 declaration with absent or case-insensitive UTF-8 encoding; a UTF-8 BOM is preserved. Other declared versions/encodings, proxies, anonymous/unsupported elements, missing name attributes, archive rewrites and companions refuse. Application version, metamodel namespace and XMI version remain distinct claims.

Escaping retains the existing quote style. Ampersands, less-than and the selected quote delimiter are escaped; CR/LF/TAB are character references so the requested decoded name survives XML attribute normalization. Invalid XML 1.0 characters and oversized values refuse. The output goes through the identical bounded `semantic-set/2` reader before persistence. The receipt binds the old and new source identities and warns that source rename is not a global semantic refactor: name-based expressions, qualified-name consumers and Arcadia/external-tool acceptance remain unverified. Fresh-read preconditions do not monitor later changes to the source during persistence.

Raw copy and edit persistence share an app-owned wrapper around actual Craft private staging. The stage lives inside an exclusively created private directory; hard-link placement refuses every existing destination leaf, including dangling symlinks and entries arriving after inspection. Filesystems without hard-link support refuse; there is no overwrite/follow-link fallback. This is a destination-leaf guarantee, not protection against arbitrary replacement of ancestor directories by another actor. Post-creation verification errors explicitly say that an output was created and must be preserved for inspection.

Draft regressions cover existing/racing destination entries, dangling-link no-target creation, private modes/stage cleanup, fresh source/span binding, both quote styles, BOM/declaration/CRLF/entity/Unicode handling, exact prefix/suffix preservation, original IDs/reference spellings/endpoints/unit strings, and all three supported classifiers. The earlier 38-test desktop/core receipt excludes this entire batch and remains unchanged. Native adverse-race/failure cases and non-Mission native authoring remain explicitly unqualified; controller injections are separate.
