## Prerequisites before wider semantic or companion intake

The reconciled peer record `docs/continuation-m1/peer-review/KERNSPAN_RECONCILIATION-r01.md` is an observed comparison, not a shared product/schema adoption. Its three peer contract hashes remain the root-owned evidence. M2 must first close these prerequisites:

- Split exact namespace/type tables. A UML20131001 namespace does **not** qualify Capella-only local names such as ComponentPort, ComponentExchange, SystemComponent or LogicalComponent. These false friends must remain Unknown with an actionable qualified-type diagnostic. The Capella fa correction must not broaden the UML table accidentally.
- Introduce a supplied-source-set digest and member-scoped endpoint keys **before** any companion binding. Proposed key: `{source_asset_sha256, member_logical_key, original_element_id}`; keep the original ID separately. Hash a versioned canonical, sorted manifest of all explicitly supplied primary/member/companion/dependency logical keys, exact hashes and roles. Absolute workstation paths are inert provenance, not portable identity. Same raw ID in two members is permitted; duplicate ID within one member refuses. `#id` resolves in its own member; explicit `logical-member#id` resolves only within the supplied set. Unknown hrefs stay unresolved and never trigger file/network access. Opening AIRD alone cannot claim it is bound to a particular Capella source.
- Add aggregate output budgets before broader projection: attribute count/individual bytes/total bytes, derived-text total bytes, projected DTO bytes and diagnostic count/detail bytes. Initial proposed software-resource budgets are200000 attributes,64KiB per attribute value,8MiB aggregate attribute values,8MiB derived text,32MiB projected DTO data and512 diagnostics with bounded details. These are implementation-resource proposals, not engineering acceptance thresholds. Preserve source bytes even when the semantic projection is refused/incomplete, label omitted scope explicitly, and refuse native admission. Do not silently truncate values and call the resulting graph complete. Diagnostic overflow must produce one bounded omitted-count record, without unbounded repeated content.
- Keep raw-central-directory/name-encoding and duplicate-member vectors specific to the actual pinned zip0.6.6 implementation; a different product's ZIP behavior is not proof for this reader. Preserve current source/expanded/member/depth/reference bounds as well.

Separate future assurance reconciliation remains pending: explicit truth Supported/Refuted review and supplied-artifact producer completion attestation need their own deliberate contract. This semantic adapter must not infer truth, adequacy, success or Passed from imported lifecycle enums, LinkedText, a calculation or a source example. It does not resolve that separate product-policy difference.

## Recommended editable admission boundary

The first faithful editable target should be a source-specific application document profile, proposed `mbse-craft.capella-slice/1`, with source IDs, exact QName/type contracts, stored attributes, typed relationships, derivation locators, immutable source assets and retained unknown properties. It is separate from `kernspan.stage1/2` and `kernspan.stage1.sysml/1`. This is the recommended implementation design for integrator reconciliation, not an already implemented interchange promise.

Initial operations: edit retained name/description drafts; set actor/human flags only on supported Component subclasses; add/remove explicit CapabilityExploitation and MissionInvolvement using existing source identities or new application IDs; edit typed property values while retaining their source type; revise constraint text only as unevaluated text. Each command validates owner/type/reference closure atomically, retains invalid raw input separately, and supports Undo/Redo and durable independent save/recovery. Original Capella/MDZIP bytes never change. Save a versioned application sidecar, or export an exact original copy; transformed Capella/AIRD/MDZIP roundtrip is outside the first batch.

Any optional projection into current Stage1 needs a separate explicit candidate transaction and loss report. A selected Mission/Capability label and a declared exploitation link must retain their source type/IDs and direction. A Capella Mission is not silently adopted as a normative SysMLv2 Mission; a constraint/property value is not silently reclassified as Objective/Measure, and actor involvement is not dropped. Unsupported roles, hierarchy, units, stereotype layers, allocations, expression semantics or cross-resource references in the selected closure refuse the **whole candidate** before native changes. Actionable refusals identify source ID/QName/feature and offer inspecting the source slice, selecting a smaller closed subset, or retaining the external source document. The preview must show omitted scope and preserve the active dirty native model until explicit commit. Unknown opaque source properties stay retained and may force closed Stage1 SysML export refusal.
